# OZL C 版玻璃与动效重做

用户已明确批准按 C（WPF UI／现代 Windows）重做，不再重复确认。顺序固定为软件视觉完成、后台验证、从同一源码生成新截图，然后更新线上官网。工作目录仍为 E:/Projects/OrangeLauncher，当前目录分支 redesign/c-glass-motion，无新工作树。

## 视觉目标

当前问题不是缺少 blur 声明，而是大面积实色白板、背景没有可透出的层次、选中态和切页只有很短的淡入。新版本应一眼看出玻璃体积和动态关系，而不依赖解释。

保留现代 Windows 的简洁布局与 OZL 橙色品牌，以有景深的冷中性背景承托分层玻璃。导航、命令栏、三个核心组件和弹窗具有实际透明背景、柔化透射、内外高光及边缘折光式渐变；主内容不再是一整张实色白纸。深色主题为石墨玻璃，浅色主题为乳白玻璃。长列表与输入控件保留稳定、清晰的阅读底层，不把逐行模糊当作质感。

保留原首页封面及原作者模组封面，不新增 AI 图、外部图片、字体或动效库。避免高饱和紫色光斑、厚重泛光、无限漂浮和指针追随。玻璃通过现有 HTML/CSS/JS 表现，不迁移 WPF、不声称实现物理精确光学折射。

## 软件动效

导航选中面在原位置到目标位置间连续滑移；切页呈现有方向的轻位移、轻缩放和透明度组合，约 320–420ms。控件悬浮／按压与浮层开合约 150–260ms，有明确的抬起、压下和落位。禁止仅把原 7px/220ms 淡入换成另一个数值交差。

动画不阻塞点击、输入、保存或异步回执。同页状态刷新不重播；快速导航取消旧动画；隐藏和减少动态效果设置生效时终止非必要动画；resize 后导航指示仍对齐。透明与模糊不受支持时有可读实底回退。不能在原生桥接、进程状态或用户配置上新增限制。

不运行或恢复已被 Defender 检测的 EXE，不重打包产品、不触发 CI、不发布产品版本或更新 feed。UI 验证仅使用真实应用 DOM 和已有合成原生边界的无头浏览器，不启动游戏、Steam 或服务器，也不打开前台窗口。
