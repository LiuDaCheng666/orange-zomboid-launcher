# OZL Fluent 工作区重排

## 已确认方向

用户选定 C（WPF UI／现代 Windows）的质感，其余由我们按此前建议实施：管理页参考 Modrinth 的紧凑信息结构，首页保留 Playnite 式封面表现。用户明确“软件页面大修，网页小修”；外部面板已确认是 `orangezl.com` 官网，不是 8790 服务器管理后台。此前要求不反复确认、后台验证继续有效。

这次必须改变实际空间结构，不以字号、圆角微调冒充改版。沿用 `E:/Projects/OrangeLauncher` 当前目录，在 `redesign/fluent-workspace` 分支实施，不复制工作树。

## 启动器

### 框架和首页

- 顶部为轻量应用工具栏；六项主导航从顶部横排改为左侧固定导航，使用原创线性 SVG 图标、名称和明显选中条。二级导航位于右侧内容区顶部。游戏识别和选择目录保留可见入口。
- 桌面侧栏约 208–224px，中等窗口可收窄；900px 以下采用约 64–76px 的图标栏，保留可访问名称和悬停提示。500×760、733×507 也能到达所有主页面和工具，不遮挡内容。
- 首页改为横向大封面在上、启动工作条在下。封面在 1440 宽时占内容区至少 90% 宽，不再与窄启动列左右并排。保留原图和轮播、暂停、版本／内存／组件摘要；不拉伸图片，不伪造游戏状态。
- 封面下启动条呈现游玩配置、目标、主启动按钮；目标为服务器／存档时完整保留对应选择。配置编辑／导入／预览／重新读取、Java 授权与详情仍能展开操作，计时和最近目标仍保留。四项常用工具继续直达内存、缓存、重下工坊和模组管理。

### 质感、内容页与动效

- 两套主题保留；以低饱和背景、不同明度的内容表面、细高光边缘、适量阴影建立层级。玻璃只用于导航、封面信息与浮层等局部，不对整页文字或长列表重模糊。OZL 图标、橙色品牌、原作者封面不变，不生成新图片。
- 组件仍为三个独立核心卡片＋可展开附加组件，但重新组织封面、标题、版本、状态与操作，禁止巨图和大面积空白。状态有文字＋颜色，更新／失败／已启用明确区分。
- 模组工作区压缩配置入口和工具栏，主体采用紧凑列表＋右侧详情。1280×900 的合成常规列表至少完整显示 6 行；不缩小正文到难读、不隐藏必要警告或操作凑数量。
- 存档、服务器采用水平图文卡片，预览图有固定合理比例；内存页改为分配编辑器＋紧凑系统指标；设置、维护、帮助和任务／授权／编辑弹窗采用同一套分组和控件节奏。移除标题周围无意义装饰文案，不新增口号或防御性说明。
- 保留现有有限时长、可取消的导航和封面动效，补充 140–220ms 的控件／浮层表现可选。动画不能延迟点击或保存；同页刷新、滚动不重播入场；快速切换、隐藏、减少动态效果时正确停止。无无限装饰动画或指针跟随。

## 官网小修

官网保留暖白／橙色、现有三个页面、五类功能说明和当前下载／源码／QQ／备案入口。只改善导航、首屏比例、功能预览框和局部质感，使其与新启动器呼应。十张应用截图在软件视觉通过审查后重新导出，不放旧版本截图，也不增加历史下载区、宣传套话、动画背景或新依赖。

## 边界

不改 C# 原生行为、请求名称／载荷、数据结构、安装／卸载／更新协议、Steam 或游戏配置；不新增进程状态编辑限制。保留 11 路由、草稿、焦点、列表滚动、失败／取消／迟到回执等交互。改版只使用现有 WebView2 HTML/CSS/JS，不迁移 WPF、不增加运行资源文件或 CDN 依赖。

本轮保持 source VERSION 1.2.14，不发产品二进制、安装器、远程构建或更新清单；不恢复隔离文件、不改防护设置。官网先完成本地源文件与验收，不在未发布软件时悄悄切线上下载／网站。源码按既有授权审查后合并、同步；交付明确区分源码、预览和线上版本。
