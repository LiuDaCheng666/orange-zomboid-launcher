# 游戏运行时更新启动器与下载完成确认

2026-10-15。用户要求修改1.2.1／1.2.2更新体验，已明确选择：**下载完成弹出一次确认，确认后自动更新并重新打开启动器**。本书面规格待用户复核；此阶段不修改运行代码、不触碰真实游戏或现有安装。

## 背景与边界

当前 `ModernController.AssertCanRestart()` 无条件调用 `Running()` 并拒绝游戏运行；检查与下载本身没有这条限制。`CoreUpdateService` 完成校验后只进入Ready，Web必须手动点按钮才确认并调用原生 `coreUpdateApply`。原生助手已负责等待旧启动器退出、替换自有文件、打开新版和健康检查。

另外，`PlaytimeTracker.Start` 和 `LaunchProfiles.Launch` 使用根目录启动器EXE启动后台监控。只移除游戏判断不足以确保这些后台实例不会影响替换文件；本次必须同时核验、隔离这两个受管后台任务的程序副本。

只改变启动器核心更新流程，**不是允许游戏运行时安装／卸载模组、改启动参数、恢复清单或修改游戏设置**。这些既有游戏运行保护不放宽。

## 选定方案

采用“完成后确认”，不采用“下载完无提示直接重启”。前者保留明确重启决定，后者可能打断编辑，本次不新增无提示自动更新开关，也不自动检查或下载。

1. 核心更新不再单独因游戏运行而拒绝。只重启启动器，不关闭、杀死或重新启动游戏、Steam或未知进程。
2. 保留原生队列、进行中的文件修改、未保存编辑、游玩配置事务、待恢复启动会话和旧Buddy接管恢复等保护。**临时启动会话仍未恢复时继续阻止**，明确说明实际原因，不清除记录、不强行恢复运行中的游戏清单。不能把“允许游戏运行”表述为绕过所有恢复保护。
3. 已运行的其他未知程序实例或真实文件占用仍可能阻止文件替换；失败按原事务保护、记录并回退，不靠结束进程绕过。

## 受管后台任务隔离

- 正式可信核心中，计时／会话监控从工具runtime下按实际已验证EXE哈希隔离的稳定副本运行，不再长期占用根目录待替换EXE。两个角色共用小型内部副本准备逻辑，不重写计时采样或会话恢复算法。
- 副本只从当前已认证安装记录中的自有EXE取得；沿用安全路径、重解析点拒绝、哈希和并发保护。不能从Web／磁盘任意指令接收源路径、程序、URL或信任密钥。只能启动已有两种受管监控角色，静默创建窗口。
- 复制物属于派生runtime缓存，不新增十八项签名自有更新路径，不打包新第三方文件，不更换正式密钥。已启动的监控继续处理自己的游戏PID／会话，更新不重置游玩时间或提前恢复模组列表。
- 未具有正式更新信任的旧单EXE保留兼容路径，不虚称支持核心更新；可信副本准备失败时保留原有清晰失败提示，不静默降级成未经校验的可更新工作流。
- 不改造／终止玩家已经在旧版中启动的后台实例；旧版到新版的第一次迁移继续受旧代码和文件占用约束。

## 下载完成确认与界面

流程：用户主动点下载 → 完整校验并进入Ready → 无阻挡时弹一次确认 → 明确同意后原生再次检查 → 关闭旧启动器 → 应用更新 → 自动打开新版并完成健康核验。

- 只有当前界面内玩家主动发起的这一轮下载，收到匹配目标版本、任务和新回复的Ready后才允许自动提示。打开页面、启动读取、历史Ready、过期回复、重复进度或取消后的迟到结果不会弹窗。
- 每轮准备好的更新最多自动提示一次。取消／稍后不安装、不重新下载、不反复弹窗；仍保留“重启并更新”按钮，玩家之后可手动操作。
- 其他弹窗、未保存编辑、本机写任务或待恢复会话存在时，不抢夺当前对话、不关闭窗口、不自动排队无限重试；保留Ready并解释阻挡，玩家处理后点击按钮继续。未核实状态按未知处理，不猜测安全。
- 弹窗同意后重检任务／版本及未保存状态，防重复提交。复用现有原生更新入口、助手、签名、健康验证与回退，不让Web绕过保护或传递下载地址。
- Ready改称“下载完成，等待重启安装”，保留当前版本／目标版本、进度和任务日志。说明“只重启启动器，游戏可以继续；如有未保存编辑或待恢复任务需先处理”，不再一概要求退出游戏。只有健康核验成功才显示更新成功。

## 验证与交付

先取得运行失败测试，再修改代码。覆盖：游戏存在但无恢复事务时允许核心重启；所有其他阻挡仍拒绝且不改用户文件；受管后台副本路径／哈希／未知来源／重解析点／并发与真实替换；游戏样例进程和监控继续运行；计时数据不重置、临时清单不提前恢复。测试只启动受控fixture进程，不启动真实游戏或Steam。

浏览器覆盖：主动下载完成只弹一次、确认／取消、重复／陈旧／错误／取消事件、历史Ready不弹、其他对话和草稿／忙碌／恢复阻挡、确认后状态变化、防双击、两主题与小窗口、原手动入口及其他功能回归。真实原生隔离生命周期至少验证成功重启与失败回退，不把staging当成已完成升级。

版本使用尚未发布的 **1.2.3**，沿用当前工作分支，不另建工作树，不重建或替换已发布1.2.2。按现有正式信任与十八文件合同构建新目录、上传草稿核对，再发布latest；源码和版本说明一并保留。发布后验证默认旧版查询／下载和线上哈希，明确不在玩家真实安装中自动点更新。

**兼容提示：**旧1.2.1／1.2.2没有这些新逻辑，因此升级到1.2.3这一次仍可能需要先退出游戏并手动点“重启并更新”。修正从新版运行后更新后续版本时生效，不能靠替换服务器资源让已运行的旧代码改变行为。
