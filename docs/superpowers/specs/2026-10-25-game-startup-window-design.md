# OZL 独立游戏加载窗口

用户已于 2026-10-25 选择并批准独立 OZL 加载窗口，随后明确纠正视觉形式：需要 Minecraft/Forge 风格的整屏加载画面，不是普通工具窗口。顶部显示进度条与内存，中间为原有 OZL 标志和加载动画，左下角显示少量实时日志；主菜单就绪后收起，游戏授权弹窗让出前台。

## 行为

覆盖进入主菜单、继续存档、连接服务器三个现有入口，不改变它们原有启动方式和预检。使用当前 1.2.16 的已附加工作区，保留所有网站、部署、SSH 与 HTTP 防护变更。

加载画面无系统标题栏、无工具页边框，不新增任务栏窗口项，占满启动器所在显示器。中央显示原有六角 OZL 标识及加载动画；顶部显示阶段进度条和实时内存，左下角直接绘制最近 4–6 行本次加载信息，右下角轻量显示用时和收起入口。原始日志留在本地，不能把大日志文本框当作整屏主布局。进程内存使用系统总物理内存作为条形图分母，配置的 Java 堆上限单独标明，不能冒充实时 Java 堆使用率。没有可靠总量时使用动态阶段条，不编造百分比。

启动会话使用唯一 ID、发起时间、游戏绝对目录；只绑定此后创建且程序路径匹配的客户端进程，排除服务端、其他 Java 程序和旧进程。增量读取该用户 console.txt，限制读取量/行长/历史条数，处理覆盖、轮转与半行，显示前脱敏。旧日志不能导致完成或失败。

就绪必须使用已经核实的实际游戏日志/现有启动桥证据；命令行包含 MainScreenState、出现游戏窗口或普通 Lua 模组名称都不能当成就绪。拿不到就绪证据时继续显示可关闭的观察窗口，不假报完成。授权等待给出清楚提示，窗口不置顶、不循环抢焦点。失败/提前退出保留最近日志与原因；没有新日志时显示等待情况，不杀进程。

关闭加载窗口只停止观察，不终止游戏、不回滚已经提交的存档/服务器启动会话。重复点击不能产生多个加载窗口。关闭启动器会清理观察任务。观察器故障不能阻止实际启动。

## 实现边界

增加原生 WinForms 整屏画面和只读后台观察器，复用现有主题、进程识别和日志脱敏；不引入 Java 注入、JMX 端口、新下载助手或新服务。原版默认日志无法证明主菜单就绪，调试标记还要求游戏调试模式，因此已告知用户复用既有一次性 Lua 启动桥：普通启动也暂时加载该自有桥，沿用原 Steam URI；save/server 沿用既有桥。菜单真实可见、初始延迟结束且 TOS 关闭、nonce/TTL 验证通过后输出本次独有的就绪标记。退出或失败后按原有事务恢复临时配置，不修改游戏二进制或 Java 启动参数。ModernController 发出类型化启动呈现事件，ModernForm 在 UI 线程管理画面与观察器，UI 不轮询完整控制器、不长期持有修改任务锁。

验证包括纯状态与日志会话测试、三入口事件边界/失败测试、真实原生窗口深浅主题和缩放截图、取消/关闭不杀游戏测试，以及原有启动相关回归和生产构建。使用自有临时目录和测试进程；不操作用户正在运行的游戏或服务器。此次实现和可测试构建不自动发布版本，也不触碰网站。
