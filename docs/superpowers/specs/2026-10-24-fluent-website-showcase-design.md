# OZL 官网：C 质感、可见动效和可读预览

## 原因和决定

用户否定了上轮官网“小幅暖白样式修饰”，要求真正落实此前选定的 C（WPF UI / 现代 Windows）质感，动画看得见，图片比例合适。沿用此前“不反复确认、后台实现”的指示；本轮不再把冷浅色 Fluent 质感仅用于启动器而保留另一套官网外观。

主控在 1440×900 实测旧官网：1440 原图显示宽 840px、缩放 58.3%；初次软件截图顶部约 723px；切换动画仅 8px / 240ms。此前测试证明存在动画，却没保证展示面积和可感知程度。本次只改官网展示，不改启动器功能。

## 新版空间与图片

- 冷浅灰蓝画布、细亮边缘、适量投影，局部玻璃导航/预览工具栏；保留 OZL 橙色标识和已有原图，不用第三方图标代码或新 AI 图。
- 取消原先“左侧长文案＋右侧小风景照片”。顶部为紧凑、居中的功能标题、简介、下载入口，下面直接展示真实新启动器的大幅窗口。
- 五类功能切换改为横向或合理折行的导航，标题和简介全部保持可见。图片独占主要内容宽度，不再给左侧说明列挤到约 840px。1440×900 和 1280×900 下软件截图宽至少 1050px，完整保持原始 8:5 比例；第一屏至少可见 180px 图片区域。手机按可用宽度等比显示，支持原尺寸大图；不裁掉应用内容、不用固定高空黑条，不拉伸。
- 三页共用一套清晰导航与控件，功能、说明和下载区分组合理；1440 宽首页总高不超过 2700px。保留五类说明和具体功能，不能靠删说明或缩小文字凑高度。

## 动效

- 首屏文字/导航/软件窗口分层进入，有限 450–650ms，最多 120ms 的细微错峰；内容始终可点击。软件窗口入场可以 16–24px 平移与 0.985→1 的轻缩放组合，不做持续漂浮。
- 功能切换采用 300–420ms 的短过渡，16–24px 平移/淡入；选择立即更新，不等待动画结束，不轮播/抢走用户选中的功能。
- 图片切换兼容加载失败与快速切换，旧加载回执不能盖回最新选择。必要时显示明确、简短的载入失败与重试入口，不虚构成功或进度。
- 新动画只改 opacity/transform；浏览器减少动态效果、页面隐藏、离开、关闭或快速切换时取消旧效果。同页滚动不反复播放。无无限装饰循环、指针跟随或 CDN 依赖。
- 通过真实渲染中间状态、取消/减少动态效果与实际 8–12 秒无头浏览器录屏验证，不以静态截图代替动效检查。
