# GitHub 官方更新查询限流回退

用户已选择“加入官方备用路径后再发布 1.2.1”。本规格只处理这条发布阻碍，不修改游戏、Steam 或模组安装行为。

## 设计

- 首选保持当前 GitHub `releases/latest` API；成功时沿用当前正式版标签校验和固定版本下载地址。
- 仅 API 查询返回 HTTP 403 或 429 时，改读同一仓库 `releases/latest/download/update-manifest.json` 和 `update-manifest.sig`。不带登录凭据，不嵌入令牌，不使用代理镜像。
- API 404 仍表示未发布；回退下载 404 同样表示暂不可用。其它网络错误、非法 API 元数据和签名失败不伪装成成功，也不反复重试。
- 两份回退文件仍由现有嵌入公钥、原始字节签名、版本／平台／文件路径／下载地址规则验证；安装、差量下载、哈希和健康检查重启事务保持不变。发布切换导致清单和签名来自不同版本时安全失败，玩家可重新检查。
- 两条网络路径仍使用现有 HTTPS 主机白名单、重定向次数、超时、取消和响应大小限制。

## 替代方案

保留当前实现只提示稍后重试，改动最少但当前真实限流仍阻断更新；让玩家登录 GitHub 或内置访问令牌则增加不必要账户／密钥管理。本次按用户选择采用仅官方地址回退。

## 验收

先用本地 HTTP fixture 取得真实 403／429 WebException，证明旧查询代码不能回退；再实现最小修复。覆盖正常 API、403／429、404、500、取消、缺失或过大回退文件、无效元数据、签名破坏和混合发布文件。测试网络边界外的查询解析和签名验证必须使用生产代码。

回归通过并独立复核后，重新生成并签名 1.2.1 发布包。GitHub 发布完整资源后，分别实测新客户端的官方回退查询、旧受信任客户端的检查和下载，以及既有隔离原生重启生命周期。旧版本在匿名 API 仍被限流时不会凭空获得新回退代码，首次可手动安装完整新版；不得隐藏这个边界。
