# OZL Velopack migration

Approved in chat on 2026-10-25: replace the custom updater/uninstaller with Velopack, keep both an installer and self-updating portable ZIP, retain the current check/download/confirm-restart UI, and stop retrying the quarantined 1.2.15 artifacts. Work in this attached worktree; the original checkout has an unrelated portable-only implementation in progress and must remain untouched.

Use upstream stable Velopack 1.2.161, MIT licensed, and its net472 SDK with Newtonsoft.Json 13.0.4. Pin public package URLs and SHA-256 values before executing tools. The existing Framework compiler and .NET 8 runtime may be used if upstream tooling supports them; install a project-local SDK/runtime only if necessary, without changing global configuration.

The main launcher selects Velopack distribution from an embedded build marker. Diagnostic/legacy builds retain their existing behavior. New published packages contain no custom updater or uninstaller executable. Velopack's own Update.exe remains a required, disclosed framework component. Do not include the old detected binaries or reconstruct them.

Keep authenticated publication metadata: a new signed RSA/SHA-256 envelope describes the exact Velopack release version, full package name, length and SHA-256. Verify it using the existing embedded trust key before offering or applying a release. Refuse tampering, replay, foreign origins, unexpected filenames, overlong responses and mixed releases. Use HTTPS on orangezl.com first, GitHub fallback on transport failure. Do not downgrade signature/integrity failures into successful fallback. Legacy feeds remain on the previous stable release until an explicit compatible migration exists.

Preserve validation of shipped Web and bridge assets from signed bootstrap metadata. Keep mutable WebView profiles, runtime state and authenticated background-worker copies outside Velopack's replaced current directory. Portable data remains within its enclosing portable folder. Normal configuration and game/Steam/server behavior are unchanged. Existing unsaved-edit, queued-write and restart guards remain in force; updates require the existing user confirmation.

Build a fresh 1.2.15 candidate from current source in a new output directory, with installer, portable ZIP and upstream update packages. Do not modify historical releases, sign historical bytes again, change protection settings, restore quarantine, launch foreground windows, or repeatedly scan/rebuild to change detection. Normal tool failures must be diagnosed once and reported accurately. First migration from custom 1.2.14 is by manual installation/extraction into a fresh directory, with explicit data-import behavior; subsequent updates use Velopack.

Acceptance: real signed-feed tamper/replay/cancel tests, actual framework-backed update discovery/download in an isolated fixture, current UI regression suite, production boundary and license checks, inspected package membership, and isolated install/portable update lifecycle tests where supported. Record skipped or blocked native checks separately. Public GitHub/website publication remains a separate final action after concrete candidate validation; this migration must not replace the live old feed prematurely.
