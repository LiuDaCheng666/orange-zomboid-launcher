# 橙子启动器 Steam 下载与旧参数接管及内存设置修复

1.1.1 修复三个问题：Steam 在线时订阅状态刷新稍晚而安装失败，手动安装 ZombieBuddy 后启动参数冲突导致工具不能安装，以及实时剩余内存限制下次启动的 Java 堆设置。保留游戏本体、存档、模组清单、Java 授权和第三方光影文件；只修改本规格涉及的启动参数，不修改注册表或系统分页文件。

玩家已确认接管旧 Steam 启动选项时可以在单独同意后一次性退出 Steam、清理冲突并重新打开 Steam。普通安装和下载不要求退出。内存规则按用户要求改为由总物理内存决定，以下数值规则供本轮规格确认。

## 已定位的问题

`SteamWorkshop.EnsureSubscribed` 在订阅请求返回后只读取一次订阅标志。用现有函数模拟订阅结果已成功、客户端标志下一次读取才刷新，可复现“Steam 尚未确认订阅”，随后状态已经是已订阅且已安装。现有测试只覆盖订阅函数同步改变标志的情况，未覆盖延迟刷新。该复现证明程序存在误判路径，不代替问题玩家机器的在线复测。

Steam 将订阅、客户端下载状态及本地安装状态作为不同接口结果。订阅成功不能冒充文件安装完成，本地文件存在也不能冒充当前账号已订阅。具体约定见 [Steam ISteamUGC 文档](https://partner.steamgames.com/doc/api/ISteamUGC#SubscribeItem)。报错中的“子进程已退出，释放游戏身份”是清理结果，不应掩盖真正失败原因；Breakpad 初始化输出不能单独作为 Steam 连接失败判据。

`Engine.Guard` 对所有账号文件中的所有 `LaunchOptions` 使用文本匹配，没有限定 App108600；发现 Buddy 参数就拒绝操作，没有接管流程。启动 BAT 也使用宽泛匹配。误识别其他游戏、无关文本和重复参数都必须避免。

内存策略使用总量扣除系统余量与“当前空闲减 2 GiB”的较小值作为上限，保存前再按瞬时可用内存检查一次。前端、旧界面输入框和后端均受影响。本机一次实际读取为总量63 GiB、可用23 GiB、设置上限21 GiB；后台占用改变即能改变设置权限。

## Steam 在线订阅与下载

修复两个使用共同订阅检查函数的入口：组件下载子进程和内置 Steam 工坊下载。已有订阅不重复请求，新订阅只请求一次；验证成功结果对应正确条目后，继续处理 Steam 回调并等待当前账号的订阅标志确认。订阅请求结果沿用各入口现有时限；结果成功后的标志刷新等待最多15秒，每次检查间隔不超过100毫秒，逐次检查取消，进度文字最多每秒更新一次。展示“等待 Steam 同步订阅状态”，不通过固定睡眠后直接宣告成功。

订阅返回错误、条目不匹配、登录失败、取消和超时仍拒绝激活。确认后继续原有下载结果、App108600、实际安装目录和组件文件结构校验。不能简单删除订阅检查，不能以文件夹存在或成功发起下载代替完成。回调处理不得丢失同时到达的所选条目下载结果。

成功重用本地完整文件时说明“使用已存在的本地文件”；没有联网下载就不显示下载完成。失败显示具体阶段和原因，清理子进程只作为附加说明。诊断记录条目、状态、阶段和耗时，不持久化原生输出中的完整 Steam ID 或凭据。平时关闭 Steam 不能作为下载修复步骤。

## 手动 Buddy 安装接管

先只读扫描选定的游戏目录及当前 Steam 账号的 App108600 启动选项，展示冲突位置与将处理的 Buddy 参数。只有确切识别的旧 Buddy Java 代理、原生加载器参数和重复项可处理；其他 Java 代理、游戏参数、内存参数、其他游戏及其他账号配置必须保留。不能将包含“ZombieBuddy”或“zbNative”的任意字符串都视作可删除参数。

在组件安装遇到已确认冲突时提供“接管旧启动参数”，维护页也可主动扫描。玩家确认后才开始迁移；界面必须明确一次性退出 Steam 的影响。不能在启动软件时自行接管，也不能通过页面传入的任意文件路径、账号或命令选择修改目标。

处理顺序如下：

1. 检查游戏确实已退出、没有未恢复启动会话、没有其他工具写入或工坊维护任务。游戏仍运行则停止，不强杀游戏。
2. 绑定当前账号和选定游戏，记录相关启动项的原值与冲突摘要。取消时不修改文件，也不退出 Steam。
3. 只有需要修改 Steam 自己的启动选项时，才在玩家单独确认后正常请求所选客户端退出，最多等待30秒；仅处理游戏 JSON/BAT 不要求退出 Steam。退出失败、无法确认身份或发生账号切换时不写 Steam 配置，不强杀任意进程。
4. Steam 退出后重新读取当前文件，保留它退出时正常刷新的无关内容。若目标启动选项变化，拒绝沿用过期预览；不能因为无关配置变化而用旧整份文件覆盖新内容。
5. 仅修改当前账号 App108600 的目标字段及选定游戏内识别明确的启动配置。游戏 JSON 和 BAT 中只移除或规范化已识别的旧 Buddy 参数；不删除模组本体，不清空整段启动选项，不改变其他参数。复杂或不明确的 BAT 语句保留并给出人工处理说明。
6. 修改前保留可恢复原值与原文件，按文件原子替换并复核。多文件失败尽量恢复本轮自有改动；外部已变化的文件不得被旧备份静默覆盖。保留阶段记录及人工恢复说明，下一次打开可识别未完成迁移。
7. 重新打开同一 Steam 客户端，不代替用户登录、接受 Java 授权或启动游戏。显示“旧参数已接管”，重新读取实际状态；只有所需文件和正常启动配置确实完成校验才标记组件配置完成。安装失败须保留真实的部分完成状态，不宣称全部成功。

Steam 未运行时不需要退出；无法确定当前账号时不猜选另一个账号，不能把未核实的 Steam 项标记为已接管。已有正常 JSON 原生 Buddy 配置不算冲突。Buddy 的自定义目录或选项不明时保留并提示，不能静默改变实际 Java 授权目录。迁移后的基础组件仍由现有安装和卸载流程管理，关闭3D时旧外部启动项不能重新激活 Buddy。备份和诊断不得在界面或日志中泄露其他启动项里的账号密码。

同一个限定到当前账号 App108600 的只读启动项解析器用于安装冲突、Java授权的外部覆盖检查以及相关启动快照。其他游戏中的代理不能导致本游戏授权被拒绝；本游戏真正的未知授权目录覆盖仍须拒绝，不能降低授权校验。无关Steam字段的正常刷新不得被当成本游戏启动选项发生变化。

## 内存推荐与保存

总量采用操作系统识别的总物理内存，不加上分页文件或显存。维持当前可用内存的读取与显示，但它只能产生风险提示，不能参与推荐值、输入上限、预设按钮可用性或保存拒绝规则。

本轮推荐起点为总内存的四分之一，四舍五入为整数GiB，半数向上，最高推荐16 GiB；推荐值不高于固定设置上限，非零可设置范围内最低1 GiB。它是起始建议，不表示重度模组最佳值，不在读取或刷新时自动应用。约16、32、64、128 GiB总内存的推荐起点分别为4、8、16、16 GiB。

固定设置上限继续为总内存扣除至少4 GiB或25%的系统余量，余量取较大者，按整数GiB计算；去掉“当前可用减2 GiB”的分支。总量相同而实时可用不同的两次读取，推荐与上限必须相同。例如总量64 GiB的固定上限为48 GiB，当前只剩12 GiB时仍允许保存28 GiB，但提示当前其他程序占用较高。系统识别本机总量63 GiB时，上限47 GiB、推荐16 GiB；不将63显示成精确安装容量64。

已有Xmx按实际值显示，不因可用内存下降悄悄截低编辑值。超过固定总量预算的旧配置也保留原文件及真实显示，给出明确提示，只有用户主动保存才修改。低可用内存不新增必须确认弹窗、不使保存变灰、不拒绝合理的手动值，也不在保存前再次按空闲内存拦截。

后端保留整数与合法范围校验、游戏退出要求、启动配置变更检测、路径边界、原子替换与恢复资料。继续统一各Windows启动分支的Xmx、去除重复项，必要时只把高于新Xmx的Xms调低，保留其他代理和JVM参数。不启动游戏、不改Windows分页、不分配设定大小的内存。

界面区分“系统可见总内存”“当前系统可用”“基础推荐”和“设置上限（按总量）”，不再把瞬时上限称为本机安全上限。现有预览数据、旧界面和现代页面使用同一规则。

## 验证与交付

新增失败回归先证明延迟订阅、旧参数接管和低可用内存三类问题，然后实施。开发测试不改变真实Steam订阅、不退出用户正在运行的Steam、不修改真实游戏配置或授权。使用隔离数据与可控进程夹具验证退出、取消、超时、身份变化及故障恢复。

关键验收包括：

- 订阅标志延迟刷新可正常完成，已有订阅只检查，不重复提交；拒绝、取消和永久不确认不计成功；原有下载校验保留。
- 当前账号的当前游戏可接管，其他账号/其他游戏中的相同文字不阻止操作、不被修改；引号、空格、重复项与JSON各Windows分支不丢失其他参数。
- 游戏运行、旧预览、Steam退出失败、并发修改、写入失败及迁移中断不造成不可恢复的启动配置；来源不明的参数拒绝自动删除。
- 同样总量在可用1、12、50 GiB等情况下推荐、上限不变；低空闲下保存28 GiB仍可完成，不修改无关参数；读取不截低已有配置。
- 两种主题、小窗口与高分辨率下显示迁移阶段、最终结果和内存提示，取消与失败可区分，原有Java批准仍须玩家逐项决定。
- 全量原生、浏览器、安装包、签名、真实本体升级和回退回归不退化。

源码保留在当前本地功能分支，不额外创建工作树，不合并或推送main。版本定义与三个EXE、安装记录、界面、签名清单均升级为1.1.1，并更新CHANGELOG；不改用测试公钥、不覆盖正式私钥、不重新附带第三方光影。生成新的安装包、完整解压包和文件级更新资产，保留1.1.0成品和失败证据。线上Release上传另行处理，本机验收不冒充问题玩家机器或线上渠道已验证。
