# 服务器模组准备：纯客户端记录与导入

用户已选择“纯客户端记录＋导入，不改服务器”。在现有工作目录和分支实施，不重复确认。先完成文案与联系群入口，再实现本功能；不改变游戏命中、Java授权或服务端文件。

## 已核实的协议

只读检查本机42.21.0的原版`projectzomboid.jar`及原版Lua，未运行游戏：

- `GameServer.setupSteamGameServer`发布`mods`与`modCount`。前者按完整ModID边界截至128字符；没有发布完整WorkshopItems。因此不能将大厅摘要当完整工坊列表。
- `ConnectToServerState.WorkshopInit`从服务器连接数据读取工坊ID与时间戳。需要工坊确认时，`WorkshopConfirm`通过`OnServerWorkshopItems("Required", java.util.ArrayList<String>)`发出**全部**所需工坊ID，不仅是缺失项；原版`ServerWorkshopItemScreen:setRequiredItems`按0基Java列表读取。
- 如果项目均已就绪，Required事件可能不触发。没有事件时不能把空记录当作无模组服务器。
- `CheckMods`读取服务器ModID与顺序至`GameClient.instance.serverMods`。工坊项目可有多个子模组，因此下载顺序不等于Mod加载顺序。保持原版连接处理与现有Buddy顺序策略，不写入所有本地子模组、不添加Java桥。

Steam规则查询接口的依据：[Valve ISteamMatchmakingServers.ServerRules](https://partner.steamgames.com/doc/api/ISteamMatchmakingServers#ServerRules)。游戏当前协议以本机原版代码为核对依据，不向仓库复制反编译代码。

## 界面与数据来源

已保存服务器卡片与首页选中服务器提供“模组清单”入口。紧凑列表显示工坊ID、已知标题、本地文件状态，以及来源“连接记录／导入清单”和记录时间。未取得清单时只显示简短空状态，保留普通连接与导入入口，不拦截游戏启动。

玩家可粘贴服主提供的`WorkshopItems=...`一行或纯工坊ID列表。支持分号、逗号、换行，正整数ID以字符串保存，最多2000项／65536字符；去重保留首次顺序。拒绝其他内容，不回显或保存原始输入，避免将完整INI的密码写进日志。导入不改变默认模组、存档、订阅或游戏文件。

连接记录只来自本启动器当前一次性服务器会话：已有请求nonce和目标主机／端口关联一个固定命名的Lua缓存文件。Required事件以原版提供的字符串ID写完整带结束标记的记录；C#校验会话、端点、大小和数量后保存为端点隔离的缓存。记录不含角色账号、密码、票据。未知、半写入、旧nonce或不同端点记录不能覆盖当前清单；记录失败不打断原版连接。恢复会话前先接收有效记录，兼容旧会话格式。

缓存是“上次连接记录”，不能伪称当前服务器保证未变。没有Required事件时不覆盖旧记录；导入标明来源，不伪造服务器验证。清单和任务各有版本标识，旧响应不能覆盖新的导入、目标或任务。

## 订阅与预下载

“订阅并下载”一次确认清单后，只通过现有Steam下载服务逐项处理这些ID。每项继续核实App108600、订阅确认、SDK下载结果和安装目录，不以文件存在冒充订阅成功，不取消其他订阅、不删除工坊文件、不自动启用任何子模组。

任务立即返回并在后台执行，不锁住页面、配置编辑或其他非Steam操作。复用现有Steam工作进程和单SDK通道，不复制下载器。进度有总项数、已完成项、当前ID、Steam实际进度／字节文本；未知字节不生成假百分比。完成、部分失败、取消和中断有明确结果及日志，只有全部核实成功才显示完成。

任务的清单、服务器端点和安装位置在启动时固定；中途修改配置不会将正在下载的任务改到另一台服务器。每个下载任务拥有独立`LauncherJournal`实例，可使用同一受锁任务文件但不复用控制器的activeId，避免覆盖普通配置任务。任务状态在服务器面板可查看，任务中心保留记录。

点击普通连接仍走现有原版流程，3D、汉化与已启用视觉组件继续按现有策略保留，普通单机模组不带入；由游戏接收最新服务端Mod顺序。准备任务不修改默认清单。显式连接或关闭启动器时取消并等待**本工具自己的**Steam下载工作进程释放，不停止Steam、游戏或服务器，不新增游戏运行时配置限制，不自动发起连接。
