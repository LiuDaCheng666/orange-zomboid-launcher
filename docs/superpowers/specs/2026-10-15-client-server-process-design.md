# 1.2.5 客户端／专用服务器进程误判修复

用户已在获知根因和修法后明确要求立即修复并发布下一修复版；本文件固定该修复边界，不增加其他功能。

## 证据与根因

OZL 1.2.4 的 GameProcessGuard.IsRunning 将所选游戏 jre64/jre 下任意 java/javaw 都当成游戏客户端。只读调查实际发现启动入口为 zombie.network.GameServer 的专用服务器；没有发现客户端入口。原逻辑因此将服务端错误显示为游戏正在运行，阻止启动，并可能将服务端作为计时对象。

## 设计

- 保留原 IsRunning(game) 的保守运行时占用语义，继续保护文件修改；新增 IsClientRunning(game)，仅在证据明确为专用服务端时排除它。
- Java 身份需同时核对所选游戏 JRE 路径和真实启动入口。必须按 Windows 参数及 Java 启动选项分界解析，不能仅搜索命令行中是否出现 GameServer。客户端、专用服务器和未知分别处理；信息不可读取、不完整、PID 身份改变等不能当作无进程。原始命令行可能含服务器凭据，不写日志、不上传。
- 首页 running 状态及正常启动到主菜单采用客户端判定；普通客户端启动检查仍保留路径、配置、Buddy、Steam 参数、待恢复与重复启动保护。修改配置的检查不能被整体跳过。
- Engine 文件修改、工坊下载、接管、删除存档、临时启动配置及恢复继续受同目录服务端／未知 Java 占用保护。指定存档／服务器直达会写临时文件，服务端占用时仍可安全拒绝，不宣称所有文件操作都可并行。
- 计时只接受明确的客户端入口，不把专用服务器或未知 Java 当作游玩。原生客户端 EXE 路径判断与正常计时算法保持。
- 不重设计 UI，不修复或重装 Steam 服务，不结束任何玩家游戏、服务器或 Steam，不修改真实游戏文件、存档、凭据、桌面、注册表或分页文件。

## 交付与验证

版本 1.2.5；保留 OZL / Orange zombiod launcher、原封面、内部 EXE 名、18 条更新自有路径、既有签名公钥。历史正式资产和标签不覆盖。验证后同步 main、正式标签、安装版、免安装版、签名更新清单和内容资源；先草稿核验，再设 latest，并实际测试旧正式版本默认更新查询及下载到 Ready。

先以真实纯分类器的单元测试复现服务端误判，再覆盖正常客户端、classpath／JVM 属性中的诱饵文本、Jar／未知入口、空值、引号、大小写、路径伪装等。回归启动预检、配置／恢复／删档／工坊保护、计时、原生宿主和界面。可对当前进程做只读证据验证，不能为了测试启动真正游戏或停止服务端。副作用测试仅允许独立 TestFixtures；缺少真实 UI 或游戏内验证时如实记录。
