# 加载场景与启动耗时优化

用户已自行运行 candidate3 并确认成功进入游戏。本次根据其直接反馈继续改进现有加载功能：橙子要有明显的生长/旋转动画，前半段应显示正在做的真实工作，启动、存档和服务器加载应分别设计，重复的启动参数检查应缩短。沿用用户要求：只在后台静默测试，不操作其正在使用的前台窗口，不改网站。

## 已确认的原因

- 本机默认清单约 9 个模组，`SortForPreflight` 却建立全部 794 个模组条目，读取约 3,170 个目录和 258,714 字节元数据。单次预检约 2.2–2.5 秒，排序本身仅约 5 毫秒。
- 前端点击启动时先完整预检，原生 launch 分派后再次完整预检；前一次还不在启动任务计时内。最新原生任务另记录约 3.6 秒，不能据此认为整个按钮等待只需 3.6 秒。
- Steam 配置读取约 0.2 毫秒，当前启动守卫约 73–113 毫秒，自有 agent 哈希核验约 30–36 毫秒。不得把实际目录扫描延迟归因于 Steam 网络，也不应删掉这些核验。
- 游戏早期在 `mainThreadInit`、`ZomboidFileSystem.init/searchFolders` 和字体/平台初始化中工作，原来的显示主要从 `Loading Mods` 才收到活动。`Core.DoFrameReady` 仅更新输入，不是呈现帧的接口。
- 内存以 `%.1f` GiB 显示，造成每 0.1 GiB 才跳变；这不是游戏加载完成比例。

## 一次权威预检

自动启动只执行一次原生权威完整预检；前端不再先发起同一项全目录检查。拒绝时返回结构化报告，保留已有依赖排序/修复操作；不提交 Steam 请求，也不提前部署 agent/写启动配置。直接调用原生 launch 同样必须完整校验。

目录解析分为有效模组 ID 发现与本次选择的图元数据读取。完整保留来源/版本布局/重复 ID 判定；不能靠目录名推断 ID。对启用条目、同 ID 的所有来源及需要说明的依赖读取最新元数据，依赖存在但未启用仍报错，不能自动启用。非启用模组不需要展示资料、封面或无关图解析。首次或来源身份不确定时保留有界身份扫描，不用不可靠的长度/时间缓存充当安全凭据。

保留最新进程身份、路径、配置、恢复状态、自有 agent 当前资源哈希和最终提交检查。对关键读取集的并发修改必须重新核查/拒绝。只把正常启动文字简化为“正在启动游戏”；必要的故障/可操作错误继续准确显示。记录内部耗时供核查，不增加面向玩家的技术说明面板。

## 三种实际场景

所有场景共用实际游戏窗口和现有中文问题分析，保留左下角真实活动、右下角核心问题，均有有界文本和原有敏感字段过滤。

1. **客户端启动**：橙子从小展开、回弹稳定后缓慢旋转，外围光弧适度配合；前半段显示真实初始化、资源索引、字体/平台阶段。资源扫描计数来自实际调用，无总数时不显示百分比。热路径逐项只计数，约 250 毫秒更新一次显示；不把全部文件名刷成日志。内存提高到更细的实测单位/精度。
2. **本地存档**：独立地图区块展开的动效与阶段布局，显示真实存档名、模式、地图和实际载入状态，转换有真实计数才展示。不能继续写“正在启动游戏”。
3. **服务器**：独立连接节点/同步动效，显示友好服务器名、地图、所需模组数量及真实连接/同步/世界加载阶段；有实际下载字节/排队位置时再显示。服务器进入世界继续使用服务器布局，不切成本地存档布局。不得把多人缓存目录名（含地址/加密用户名）当作服务器名；只读取白名单字段，禁止读取连接密码/认证/QR 内容。

场景状态由实际方法、字段和事件决定：真实菜单、连接退出、取消、断开、失败、交互或游戏完成均正确交接；再次进入本地/另一服务器时清掉旧名称、计数、问题与动画操作状态。

2026-10-26 用户进一步明确：服务器页面必须显示本次连接实际取得的服务器地址、在线人数、游戏时间、游戏日期/世界第几天和进入进度。地址取当前连接输入，人数与时间优先取当前服务器的排队/同步数据；普通连接用独立、一次性且有界的公开 A2S 查询补充人数。网络工作在后台进行，超时不会阻止进入游戏；取消和切服使旧查询失效。当前服务器资料跨同一次连接的授权、角色选择和世界加载保留，另一个服务器或本地存档不能继承。游戏时钟必须经过本次同步证明，不能拿本机时钟、前一服务器或默认值填充；进度继续表示真实阶段和已知字节/计数。数据紧凑地融入原有加载画面，缺失项不加解释面板。

## 服务器交互与绘制顺序

不能把现有 GL 绘制挪到 `UIManager.render` 的 CPU 入口：游戏的 SpriteRenderer 会延后执行绘制，UI 还可能走独立 FBO。服务器/排队有取消、下载确认、授权与角色选择等交互，不能被 swap 前的全屏绘制覆盖。

对已验证的主菜单连接/排队背景路线，在 `MainScreenState.renderBackground` 之后，通过 `SpriteRenderer.drawGeneric(TextureDraw.GenericDrawer)` 入队自有背景绘制。只在这些明确路线及非 UI-FBO 帧生效，GPU 执行时再次核查操作代际/场景；自有背景先绘制，原生控件随后绘制。服务器交互路线禁用 swap 全屏覆盖。其他未验证的 UI 路线保留原生画面；实际 `GameLoadingState.enter` 后使用专门的本地/服务器世界加载布局。

运行时适配仅生成自有 GenericDrawer 子类，不打包游戏类、不替换游戏类、不改 Buddy 信任。绘制须保持游戏 GL/跟踪状态，错误只禁用自有呈现，旧排队帧不能覆盖新操作。

## 验证与交付

- 原生先复现重复完整预检，验证一次检查、结构化拒绝、排序继续启动及并发更改；针对模组来源、重复 ID、版本布局、依赖/冲突、新鲜字节、路径和当前 agent 保留回归。以只读本机基准对比，不做脆弱的绝对耗时单元断言。
- Java 验证早期阶段、节流/计数、三种场景、后续再次进入、敏感字段排除、所有交接与原方法返回/异常；实际变换匹配本机 42.21 类。
- 查看多个真实生产绘制实现的离屏帧；隐藏 GL 测试验证旋转、生长、状态恢复、FBO 和入队背景在原生控件之后不会重画遮挡；减少动态效果保持静止。
- 后台构建新候选、核对内嵌组件和包内哈希，交付用户自行测试。用户的 candidate3 成功记录不替代本轮改动后的真实游戏验收。未验证新版真实路线前不发布正式更新。
- 本轮不改版本、不访问服务器、不覆盖网页、部署或其他任务改动。
