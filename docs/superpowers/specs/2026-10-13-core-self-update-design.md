# 橙子启动器本体文件级更新设计

安装版将启动器拆成独立程序、界面资源和运行依赖。玩家在启动器内检查版本，只下载发生变化的文件，验证完成后重启启动器。更新不安装或更新游戏模组，不包含第三方光影包，不写注册表。

本规格覆盖本体更新、首次安装和安全卸载的配套改造。2026 年 10 月 13 日的范围确认是采用程序本体更新并移除第三方光影预设；本规格待用户审阅后进入实施。当前代码仍是嵌入资源的单 EXE 结构，尚不能执行本规格的更新流程。

## 用户体验

在现有帮助页面增加紧凑的“启动器版本与更新”区域，并在顶部保留轻量入口，不重做已经确认的整体布局。显示本机版本、最新版本、检查时间、更新说明和预计下载量。“启动器更新”与组件页面的“模组更新”使用不同名称和请求，避免混淆。

默认由玩家点击“检查启动器更新”。检查只读取版本信息，不下载程序、不占用 Steam 游戏身份、不修改本地程序文件。发现新版后，玩家点击“下载更新”；下载过程中显示已完成字节、总字节、当前文件、整体进度、速度以及取消入口。未成功查询不得显示“已是最新版本”。

下载和校验完成后显示“重启并应用更新”。重启前提示保存未提交的编辑；存在安装、卸载、清理、保存、启动恢复等写入任务时不得直接退出。游戏仍在运行时可以检查和下载，但推迟应用，不关闭游戏。失败原因、重试入口和结果保留在更新区域与任务记录中。

## 方案选择

| 方案 | 下载方式 | 取舍 |
| --- | --- | --- |
| 文件级更新 | 按签名清单比较文件 SHA-256，只取变化的完整文件 | 本次采用；足够可靠，界面资源更新不必下载整个程序 |
| 完整本体包 | 每次下载完整的无光影小包 | 可用于首次安装和人工修复，但不是日常更新方式 |
| 二进制差分 | 下载旧文件到新文件的差异片段 | 本次不做；需管理基线及差分失败回退，复杂度高 |

文件级更新不等于字节级差分。一个 EXE 有改动，仍下载完整的新 EXE；只有界面的 JS 或 CSS 改动，则不重复下载程序、首页背景或未变化的运行依赖。

## 安装和文件归属

首次使用提供无第三方光影的安装程序，安装到玩家选择的独立目录，并附带卸载程序。保留不写注册表的原则，不自动安装系统 WebView2 Runtime。另可提供完整文件夹 ZIP 供直接解压运行；这一版本不是单 EXE。

程序和资源成为安装清单中独立拥有的文件，包括主程序、更新助手、卸载程序、界面 HTML、JS、CSS、工具自有背景及图标、工具自有桥接资源、受许可允许分发的 WebView2 SDK 文件以及说明和许可文本。更新运行不调用当前只允许新空目录安装的旧安装器。

使用新的带版本安装记录，记录规范化根目录、安装标识、版本、文件相对路径和文件哈希。更新成功时同时更新此记录；卸载程序读取相同记录，避免将更新过的程序误判为玩家自行修改而无法卸载。未知文件和已被玩家修改的文件保留并提示，不静默覆盖或删除。

界面不再使用整包嵌入 EXE 的资源布局；本体安装记录负责核对同一发行版本的程序和页面契约。运行时浏览器缓存与用户数据不列入发布文件清单。

## 第三方光影边界

新安装包、更新文件和公开发行流程均不携带第三方光影 ZIP，也不携带原作者模组本体、源码或工坊封面。组件封面仍可读取玩家本机文件或从作者发布渠道按需获取；不换成自行生成的封面。

保留导入光影和查看当前已安装光影的功能。新安装无预设光影时使用原版选择，不宣称已经安装 Eclipse。清理帮助和界面中“内置第三方预设”“默认启用内置 Eclipse”等过时表述。

不删除玩家已导入的光影、游戏光影目录或旧私人版本已经释放到本机的资源，不为更新遍历清理游戏目录。私人测试资源可以留在本机，但新发布构建必须通过无第三方预设检查。

## 更新来源和发布

稳定更新来源使用现有仓库 `LiuDaCheng666/orange-zomboid-launcher` 的 GitHub Releases，而不是 Steam 创意工坊。发布标签统一为 `v` 加三段数字版本，程序、安装器、更新清单和用户界面从同一份版本定义生成。普通源码提交和本地合并不当作可下载发行版。

发行包含完整首次安装包、可解压本体包、签名文件清单以及供文件级下载使用的内容寻址文件。清单包含格式版本、发行版本、支持的平台、最低更新器版本、更新说明，以及每个文件的相对路径、长度、SHA-256 和下载地址。发行内所有下载对象先上传完成并校验，再对用户可见；不允许半成品发行成为稳定更新源。

下载后的确切清单原始字节必须通过发布签名验证。采用 .NET Framework 可支持的 RSA SHA-256 签名与固定受信公钥；私钥不进入源码、客户端、安装包或公开发行资产。SHA-256 只负责内容完整性，不能替代发布签名。首次发布建立并妥善保管签名密钥，后续复用；存在密钥时不得静默覆盖。

只接受 HTTPS 官方发行地址及其受限制的下载重定向。客户端不接受页面传入的任意更新网址、任意输出目录或未签名的额外文件。GitHub 访问失败、限流、超时、签名无效或更新协议不兼容时保留当前版本，展示可理解的错误与人工下载安装入口。

构建和发布脚本负责从同一构建结果生成文件清单、签名、安装包和更新文件，不人工修改线上 JSON。发布验证可以用测试密钥及本机临时发行夹具；不得把测试公钥配置成正式渠道。正式发布到 GitHub 是独立外部动作，实施和本机测试不会自动推送未发布的源码或上传发行。

## 下载和应用流程

1. 检查版本时异步请求发行信息和签名清单，验证签名、平台、版本和协议；拒绝自动降级。检查阶段有超时，可取消，不锁住导航、筛选或正常状态读取。
2. 下载前比较本机安装清单与实际文件哈希，列出需变化的文件和总大小。未变的文件不下载，缺失的工具文件列入需恢复项。已存在但哈希不同的工具文件统一视为冲突，不擅自判断是损坏还是玩家修改；要求通过明确的修复确认或新目录安装处理，不静默覆盖。
3. 变化的文件下载到安装目录下带唯一任务标识的暂存目录，完成单文件长度及哈希校验。校验失败文件不得进入应用阶段；重试复用已经校验通过的暂存文件。取消保留可继续使用的旧版本。
4. 应用前再次验证清单、暂存文件、安装记录和旧文件基线，确认磁盘空间、目录写入权限和任务空闲。没有授权提权的需求，不写注册表；不可写目录提示玩家迁移或人工安装。
5. 将当前已验证的更新助手复制到工具拥有的任务暂存目录，核对复制后的完整哈希再运行，绑定此次任务、安装根目录、原启动器进程及其启动时间。运行中的副本不作为安装目标，使正式助手文件本身也能按清单更新。助手等启动器正常退出，不能靠强杀游戏或任意 PID 释放文件。
6. 在同一磁盘写入事务记录，保留上一个有效的工具文件及安装记录，替换清单允许的文件并提交新安装记录。此短期恢复副本只用于程序更新，不是游戏缓存或存档备份。
7. 新版本启动并完成原生初始化、页面加载和宿主通信后写入健康确认。更新助手收到确认后报告成功；仅启动一个进程不算更新成功。
8. 替换、启动或健康确认失败时恢复上一版完整文件集合和安装记录。中断或重启后优先恢复未完成事务，再加载主界面，避免混合版本。记录明确的回退结果，不反复自动尝试同一失败更新。

新增文件和移除文件同样由签名清单与旧安装记录约束；只允许处理本工具拥有的发行文件。卸载与更新使用相同的目录边界和文件拥有规则。

## 安全和并发

更新器不使用游戏引擎的 `Check()` 写入路径，不修改游戏 JSON、模组启用清单或 Java 文件授权。服务器账号、密码、存档、用户模组配置、内存设置及其他已有工具数据保持原样。

签名清单和更新任务均设定严格的大小、文件数量、路径及 URL 上限；路径不得为绝对路径、父目录逃逸、设备路径或替代数据流，目标不允许经过链接或重解析点。不得通过临时目录参数执行任意程序或写入任意路径。每次落盘及最终应用前重新校验边界和哈希。

同一安装目录只允许一个下载及应用任务；重复点击不会启动多个助手。检查和下载独立于 Steam 网络通道。已有后台状态读取不能被错误地算作正在修改程序文件，也不能导致更新查询被挡住；只在实际应用时互斥本地写入和退出流程。

更新应用与卸载互斥。旧安装记录、文件哈希或任务标识已改变时拒绝应用，不沿用过期的页面状态。新版本确认前不得删除唯一可恢复的旧版。更新器只能清理自己的标记暂存目录和已确认的历史工具恢复文件，不递归删除安装根目录。

## 旧版迁移

已有单 EXE 没有本体自更新入口，不能声称会自动获得新功能。第一次由玩家下载新安装程序，装到独立新目录；之后从该目录启动并使用文件级更新。新的可解压文件夹版本使用相同协议。

沿用当前账户已有的工具数据位置，不为了迁移重置服务器列表、模组配置或授权。旧单 EXE 和新版本不同时执行修改任务。旧安装目录是否移除由玩家决定；迁移不自动清理旧程序或私人资源。

## 验证标准

- 安装器、可解压包及更新资产均不含第三方光影 ZIP、模组本体或作者封面；首次安装、更新后卸载都只处理工具拥有的文件，不写注册表。
- 从发行 A 更新到 B：只有 JS 改变时，网络记录仅有版本清单、签名和该 JS 文件，不下载背景、主 EXE、运行依赖或任何模组。
- 校验签名错误、文件哈希错误、路径越界、重复路径、非法地址、过大清单、协议不兼容、降级及签名未知来源，均在修改有效版本前拒绝。
- 断网、下载取消、无空间、文件占用、文件被玩家修改、下载后基线改变和权限不足，均保留可用旧版，错误与任务结果可追踪。
- 在文件替换及安装记录写入的各关键阶段注入中断，重启后恢复一致版本；新版本无法健康启动时恢复旧版，不进入自动重启循环。
- 多窗口、重复更新、更新与卸载、更新与组件写入以及后台读取竞态均有测试；更新过程中导航和列表筛选保持可用，未提交编辑不会未经确认丢弃。
- 更新前后服务器列表、模组配置、Java 授权、光影文件、游戏启动参数和存档的内容校验值一致。
- UI 在两套主题及小窗口下检查版本与进度显示；成功、可更新、失败、取消和回退使用清晰文字及不同状态颜色，不仅靠颜色辨认。
- 使用本机签名发行夹具完成安装、少量文件更新、重启健康确认、失败回退和卸载闭环。正式线上更新是否有效，以可信签名发行上传后从正式地址实际下载验证为准，不把本机夹具测试冒充线上发布成功。

## 实施边界

本次不实施 Steam 工坊本体分发、二进制差分、第三方光影发行、自动 Java 授权、系统运行库自动安装或游戏模组联动更新，也不改变已确认的组件卡片和模组列表布局。大厅当前忙碌误报等其他缺陷不是此规格的独立修复范围；与本体更新相关的只读查询和实际写入隔离必须单独验证。

设计审阅通过后，先补更新与安装的失败测试，再分阶段实现文件布局、签名与清单、下载任务、事务助手、界面和发布构建。交付新的首次安装包和本机更新验证报告；正式发布另行说明渠道状态。
