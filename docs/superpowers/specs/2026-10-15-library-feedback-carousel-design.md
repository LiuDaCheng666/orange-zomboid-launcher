# 存档／服务器布局、恢复反馈与封面轮换

日期：2026-10-15。用户已确认上一轮五项方案，本文将其固定为实现边界。

## 范围与现有证据

- `run('componentsAction')` 把完整批量结果写入全局 notice，`restoreResult()` 又原样显示一次；截图中的重复长面板源于双重呈现，不应丢弃底层日志。
- 存档和个人服务器沿用通用双列卡片；原版方形缩略图放在整行宽、约 80px 高的 contain 容器中，造成图小而卡片空。
- 存档当前只有读取、修改模组和实验启动，没有删除操作。
- 首页的目标类型和目标名称分成两个含糊的下拉框，主按钮始终叫“启动游戏”。
- 产品仅打包 `Web/home.png`；三张候选图在 `docs/assets/cover-candidates`，尚未接入轮播。

本轮修正这五项，不重写组件安装、模组排序、Java 授权、更新协议或服务器连接机制。保留原封面、两套主题和现有启动安全校验。

用户追加的确定命名：程序显示名及左上角改为 **OZL**，全名严格使用用户提供的 **Orange zombiod launcher**。同步窗口、安装器、快捷方式等用户可见名称；旧版已签名更新协议依赖的内部 EXE 路径暂保留，不破坏既有安装升级、快捷方式所有权和卸载记录。

## 1. 恢复反馈

恢复仍只弹一次事前确认。执行中显示任务进度；完成后只保留一处紧凑结果，包含成功／失败数量及明确状态。详情默认折叠，可展开逐项结果并前往任务／日志。失败不能伪装成功，刷新失败不能抹掉已返回的执行结果。

完整原生结果继续保存在任务日志中；不再把全部报告同时塞入全局通知和结果卡片。结果可关闭，不随普通状态轮询重复出现。

## 2. 存档与服务器

使用专用紧凑横向卡片：左侧约 112px 方形原版缩略图，右侧标题、类型／状态、修改时间或地址、模组数或在线人数／容量／延迟，以及清晰的主要操作。图片不拉伸，不使用 AI 生成的模组或存档封面；不存在图片时给出同尺寸占位。

普通桌面宽度下合理排布列表，窄屏缩小缩略图并换行，不出现横向溢出。较长介绍默认折叠，重要状态不隐藏在详情中。服务器收藏与大厅保持原有功能；个人服务器卡片优先修正，相关共享规则不得破坏其他来源的布局。

## 3. 存档删除

每个本地存档提供“删除”入口；一次确认明确显示名称、类型及本地路径，确认后仅将该存档目录移到 Windows 回收站，不提供永久删除回退。多人条目文案明确是“删除本地多人缓存”，不删除服务器世界、远程角色、已保存服务器或密码。

界面只传本机扫描得到的存档 ID 与原生预览凭据，不接受页面任意路径。原生重新解析并核对路径及预览状态，拒绝越界、重解析目录、内容已变化、游戏运行、未恢复会话及并发修改。取消确认、冲突、回收站不可用时不删除并给出真实错误。成功后刷新列表、清理已失效的编辑／启动目标；保留其他未保存草稿的保护。

测试仅使用隔离夹具和可注入的回收站边界，不删除用户真实存档。

## 4. 清楚的启动目标

将三种目标命名为“进入主菜单”“继续单人存档”“连接服务器”，配简短用途说明；存档／服务器模式必须明确选择目标。主按钮随目标显示“启动到主菜单”“继续：存档名”“连接：服务器名”。

实验直达模式仍明确标注可能停在游戏内授权／主菜单等步骤；不能把提交请求描述成已经成功读档或进服。保留游玩配置与目标绑定、未保存草稿、预检、运行中禁止重复启动等全部校验。

## 5. 首页封面轮换

原封面保持第一张，复用已制作的三张候选图，每 8 秒轮换。提供上一张／下一张、当前位置和暂停／继续；用户可固定任意一张。右下角实际版本、内存及已配置组件摘要不随图片切换而闪烁或移动。

轮播不得触发首页整体重渲染或重置表单焦点。离开首页、页面隐藏、鼠标停留或键盘焦点进入封面控制区时暂停计时；返回后恢复一个计时器。尊重减少动态效果偏好。图片加载失败跳过或保留原图，不留下空白。

选择和暂停偏好仅保存为启动器界面偏好，不写入游戏配置。候选图片必须随安装版、免安装版及受签名管理的核心包完整交付；不绕过核心文件白名单或签名校验。

兼容性约束：1.2.3 的更新器使用固定核心路径白名单，因此本轮不能通过添加新的核心路径交付候选图。将候选图作为数据资源嵌入已有受签名的 Web 文件，原 `home.png` 字节保留，确保旧版仍能验证新版本清单。
