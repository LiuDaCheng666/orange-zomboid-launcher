# 配置编辑窗口关闭后再次进入

范围：用户确认，按钮失效发生在打开、关闭编辑窗口之后。安装中的 1.2.37 与本分支 app.js 的 SHA-256 一致；最近 launcher.log 没有操作异常。日志没有记录每次前端点击，不能以没有日志推断没有错误。

已复现：浏览器原生 `dialog.close()` 后，窗口不再显示，但 `launchConfigurationUi.model.editor` 仍指向旧窗口。再次点击组件编辑入口命中 `if (model.editor) return`，没有提示或新窗口。常规 Close、Escape、放弃草稿以及读取途中 Close 的原有路径没有复现。尚不能证明用户本次触发关闭的具体浏览器事件来源。

修复设计：窗口关闭必须清理自己的编辑状态和未完成只读请求；清理幂等，旧窗口延迟事件不能清掉新窗口。再次进入时检查现有窗口是否确实仍打开并连接到文档，恢复已关闭或移除的旧引用。显示窗口失败也释放占用并允许重试。已提交保存继续执行，不因关闭界面取消；草稿保持原有一次确认。

验收顺序：

1. 为原生关闭、立即重新打开、关闭时的延迟读取、已移除窗口、显示失败、草稿确认编写真实 DOM 回归，先确认失败。
2. 修改可编辑模块与生产 app.js 内联副本，保持两者一致。
3. 后台点击上述路径，查看操作后的截图。相关原生控制器验收覆盖读取取消、重新打开、普通保存和文件结果；不操作用户现用窗口、不运行游戏。
4. 独立代码复查与验收记录，明确真实 DOM、原生控制器和未覆盖的桌面物理操作边界。不覆盖已发布 1.2.37 发行字节。
