# Velopack Migration Implementation Plan

> **For agentic workers:** Use subagent-driven-development task by task, with a scoped review after each deliverable and a whole-branch review. Do not ask for repeated confirmation; the design is approved.

**Goal:** Deliver a working 1.2.15 installer and self-updating portable ZIP using upstream Velopack instead of the two custom auxiliary executables.

**Architecture:** Add pinned upstream tooling, an authenticated Velopack backend behind the existing native/UI update boundary, stable mutable storage, and a separate package/feed/deployment lane. Preserve legacy code only for compatibility and diagnostic coverage; never execute or regenerate the quarantined candidate.

**Tech Stack:** C#/.NET Framework 4.7.2-compatible API, Velopack 1.2.161, Newtonsoft.Json 13.0.4, PowerShell, Node/Playwright, Python.

## Global Constraints

- Work only in this worktree; never edit E:/Projects/OrangeLauncher or consume its uncommitted helper-free implementation.
- Keep installer and portable ZIP, automatic update for both, and existing explicit check/download/restart interaction.
- Preserve RSA/SHA-256 authenticity, exact package length/hash, HTTPS origin constraints and cancellation. Never trust unsigned feed hashes alone.
- No quarantine restoration, antivirus setting changes, proactive scans, foreground windows, game/server changes, or secret output.
- Keep existing signing identity outside Git. Historical releases and live legacy feeds remain intact.
- User data, browser profiles and running worker images must survive replacement of current.
- Source version remains 1.2.15; fresh outputs never overwrite old candidates. Initial old-client migration is manual and documented.
