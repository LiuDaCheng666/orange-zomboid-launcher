## 现场问题与处理

第一次以 root 验证 Caddy 配置时创建了 root 拥有的访问日志，服务账户启动报 `permission denied`。根据 journal 定位，将该自有日志归属设为 caddy，并改为始终通过 `runuser -u caddy` 校验。未截断日志，未放宽系统保护或改为 root 运行服务。第二次部署服务处于 active，并通过实际 HTTP 读取。

真实响应检查还发现通用 Cache-Control 覆盖了最新元数据的 no-store 设置；新增真实 HTTP 断言先复现失败，再将页面/资源/元数据匹配器分开，复测 5/5 通过。最新签名元数据现在不存储缓存，带版本下载为长期 immutable。
