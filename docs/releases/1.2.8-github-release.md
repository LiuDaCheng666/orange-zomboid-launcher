## 根因与修复

1. 上版保留了`SaveDeletion.Guard`的全游戏目录进程检查，删除存档仍会被本机专用服务器或Java阻断；UI也以`status.running`禁用删除。现已从服务、控制器和UI去掉该运行状态前提，并移除“有直达会话就不能删除”的间接限制。确认后只尝试回收选中的准确本地目录，不停止任何进程，不修改远端服务器，也不回退为永久删除。真实文件错误照常返回。
2. `launchExperience`对所有warning再次弹确认，因此Java状态未知、封面路径和作者介绍长度等提醒每次都要求“继续”。现检查通过就直接提交启动；通过记录折叠在封面下方，只有实际阻断默认展开。每次报告独立的disclosure标识，不继承上次展开状态；Java授权仍需玩家明确决定，自动排序入口保留。

未改造其他UI、模组安装方法或重复启动识别。删除的准确目标确认、回收站能力、真实未完成文件事务、取消和文件身份检查保持原有语义；不会将“检查通过”冒充已经进入游戏。
