## 下载页评审修正与最终针对性结果

Task3 主实现 `7636bf3` 后，评审发现两处实质问题：绘制每个原生行元素时重复读取全部工坊项目，使工作量随项目数量平方增长；预览测试的滚动条宽度及裁剪边界也未完全还原原版。修正 `e5dd6e5` 将项目观察移到更新/CPU 帧边界，绘制阶段保留固定开销的身份校验；列表测试现在执行安装版原生 prerender/render 和滚动条 render，包含屏幕外所有行及实际模板裁剪顺序。

性能回归使用遍历计数而非时间猜测：旧实现在 8 项时每帧读取 1,408 项；修正后 8/24/64 项分别只读取 8/24/64 项，两帧均一致，原生所有行回调仍执行。滚动条可见/隐藏时分别核对状态徽标、长中文状态及省略号右侧边界。重新查看修正后的 640×480、1280×720 实际隐藏 GL 图，确认名称、状态与滚动条分离。

最终载荷对应结果：109 项下载/布局/身份检查通过；6 个项目数量/帧组合通过；滚动条可见/隐藏边界通过；实际裁剪及滚动条隐藏 GL 检查通过；18 项实际 API 非初始化检查与载荷审计通过。此前已通过的 23 项合成、17 项生命周期、45 项连接状态、11 项排队、32 项共享转换/生命周期检查保留证据，未因后续局部修正重复运行完整套件。
