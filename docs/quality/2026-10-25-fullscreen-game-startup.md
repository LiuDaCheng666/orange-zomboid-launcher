# OZL 整屏游戏加载画面验证

用户确认独立加载画面后，进一步指定 Minecraft/Forge 风格的整屏布局：顶部进度与内存、中央现有 OZL 标识及动画、左下角少量日志。实现位于已附加的 `codex/velopack-updates` 工作区，基于正式 1.2.16；没有改动网站或线上更新文件。

## 已实现

- 无边框加载画面覆盖启动器所在显示器，不新增任务栏窗口项。复用原有六角标识的高清内嵌资源；中央分段圆环旋转并轻微呼吸，遵循 Windows 低动态设置。
- 进度取真实加载阶段；拿不到总量时使用动态条。显示本次游戏进程物理内存与系统原始总内存，配置 Java 堆上限单独标示，保留非整 GiB 的精确字节值。
- 左下显示最近六行脱敏日志；底部显示用时与收起操作。关闭画面只停止观察，不结束游戏。
- 覆盖普通 Steam 启动、继续存档、连接服务器。普通启动仍使用原 Steam URI，只复用既有的一次性 Lua 启动桥；临时模组配置沿用已有事务和退出恢复机制。
- 游戏默认日志不能证明菜单就绪；Lua 桥仅在本次 nonce/TTL 有效、主菜单实际可见、初始延迟结束、TOS 关闭后回传独有标记。观察器只接受本次新客户端和对应标记。旧日志、旧进程、命令行和窗口出现均不等于就绪。
- Java 模组授权等待时隐藏加载画面，让游戏处理；加载恢复后显示；失败/提前退出保留原因。Steam 延迟最多等待 180 秒再恢复尚未使用的临时配置。

## 验证证据

- 组合原生测试 472 条 PASS，包含加载呈现、窗口生命周期、真实受控进程绑定、内存、日志追加/轮转/截断、nonce、关闭不杀进程，以及原有预检、启动目标和控制器回归。
- 真实 Lua 脚本在受控游戏 API 环境运行，新旧 11 组测试通过；普通启动、菜单不可见/TOS、过期请求和 save/server 保持原行为。
- 原有浏览器 quiet-launch 回归 3/3 通过。
- 原生整屏窗口覆盖深浅主题、1920×1080、1280×720及 150% 字体/布局模拟；旋转环两帧有实际差异，标识轮廓稳定。没有修改系统 DPI。
- 独立只读审查无未解决 Critical/Important；发现的 Xmx/物理内存整 GiB 舍入问题已通过先红后绿的字节精度回归修复。
- 生产分发构建和 RSA 认证清单验证通过。完整 Portable 包解压后，实际生产程序以只读预览模式成功打开、生成截图并正常退出。

验证使用自有临时目录、受控子进程和窗口；没有启动、关闭或修改用户正在运行的游戏、Steam 或服务器。主菜单事件由实际 Lua 资产测试验证，不能把这些测试描述为已完成用户实机所有模组组合的游戏启动验收。
