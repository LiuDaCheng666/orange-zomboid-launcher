# 1.2.47 服务器 Java 授权与连接展示验证记录

2026-10-31 已正式发布至自有服务器和 GitHub，正式产品提交为 `0683080a23e64bbce4f57eaed5305601e083691d`，标签为 `v1.2.47`。本记录区分实际日志、真实 Buddy 整合、隐藏 GL 场景、生产客户端更新验证及未执行的完整游戏验收。

## 原因与改动

证据根：`E:/Projects/OrangeLauncher/artifacts/connection-overlap-20261031`。用户原始截图、console、DebugLog、connections 与启动器日志均只读冻结并记录哈希；原始资料不提交到仓库。

1. 普通启动到主菜单的参数仍为 `policy=deny-new`；Buddy 在 JVM 启动时锁定策略，所以后来手动进服的新 Java 被直接拒绝。日志明确有 `Blocking Java mod by policy=deny-new: ShootToThrillMultiplayer`，不是服务器缺一份 STT 文件。主菜单/继续存档与直连统一使用 Buddy 原生询问策略，没有自动允许、代签授权或全局 allow-all。
2. 还有第二层：普通启动的 Live 清单没有 `server-components`，静态 Java gate 可能在 Buddy 已处理允许后再次拒绝服务器 JAR。现在仅在核对过的原生 `ZomboidFileSystem.loadMods(String)` 客户端作用域内委托 Buddy；正常、异常及嵌套退出恢复原作用域。调用外仍保留本地来源/包名/哈希规则，原版模式限制不变。普通手动进服跟随实际服务器清单，不让本地同 ID 来源覆盖服务器；显式强制本地组件的既有选择仍保留。
3. 展示层在拒绝接管原生页面后仍可能加入 OZL 背景，形成截图中的原生窗口/PZ 标题与加载画面重叠。修复普通连接/排队的归属要求、同帧归属失效和异常时撤票、无合法页面时的 ResetLua 展示，以及排队帧末在原生控件之后错误追认归属。保留原有橙子、布局和动画，不改原生网络连接操作。
4. 新增每次载入一条数值诊断：`totalMs`、`discoveryCalls`、`discoveryMs`、`client`。计时只覆盖当前线程本次作用域，嵌套/异常恢复后再输出，没有每个目录日志、路径/模组 ID、额外锁或缓存。`totalMs` 是经过时间，可能包含第三方操作和授权等待，不是 CPU profile。

更新后的策略需要正常退出整个游戏后，由新版重新启动。仅更新启动器、断线重连或再次加入服务器，无法修改已经运行的 JVM agent 参数和已加载的类。原有明确拒绝不会被本次修复自动改为同意。

## 实际耗时与剩余限制

真实日志中启动器调度约 5.8 秒。Buddy 三次 `Loader.loadMods()` 分别约 55.232 秒、30.346 秒、1.753 秒。可见作者列表 HTTP 连接超时；只读字节码确认同步工坊详情/作者映射/作者公钥请求及超时后缓存回退链，没有可用的公开 cache-first、TTL 或异步设置。本次未修改第三方 JAR、关闭其签名验证或伪造授权。

两个预处理空档约 61.222 秒和 63.750 秒，尚未完成因果归属。实际 514 个来源根的暖态发现过滤约 1.25–1.32 秒/次；原会话没有调用次数，不能据此把约 61 秒全部归给 OZL。原生游戏还有翻译依赖和递归目录准备，当前仅有字节码和文件枚举证据，没有真实线程 profile。本版本新增计时用于后续区分这些耗时，不宣称五六分钟载入已根治。

首次连接在原生 connections 日志 10:57:41.527 已断开；主线程直到 10:59:01.529 执行排队请求时遇到 `GameClient.connection=null`，随后处理断线并返回菜单。没有确定写空连接的调用方，不能把后一个异常时间当作首次断线时间，也不能把展示修复称为网络断线原因已解决。

未执行完整最终包进真实服务器、真实 ImGui 授权点击、正常游戏存盘退出再进或未知服务器 JAR 执行。测试均在后台控制台、无窗口浏览器或不可见 GL 中进行，没有控制用户前台或结束其游戏进程。
