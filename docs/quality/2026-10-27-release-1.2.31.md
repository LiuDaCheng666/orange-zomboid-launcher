## Update block and underlying cleanup failure

The installed 1.2.28 had a verified 1.2.29 download but rejected restart solely because an old launch-session journal existed. Its bound game process no longer existed and the managed default-list hash still matched. The native and browser restart policies incorrectly treated persisted recovery records as active application work.

1.2.30 allows application update while retaining launch/Buddy/play-profile recovery evidence. Busy native work, network/workshop work, queued mutations and unsaved browser edits remain guarded. Ordinary game maintenance/recovery ownership checks are unchanged.

The older journal was backed up, with the default list, in the current user's private LocalAppData backup directory `PZ3DManager/backups/update-unblock-70b0927bef924734bceb194241d6cbe6`. Existing installed native recovery then completed successfully, bound to the observed journal hash. No Steam restart, game launch, launcher shutdown, or foreground interaction was performed.

1.2.31 also fixes the reason automatic cleanup could leave that journal behind: the cached background worker carries only its executable, but journal validation enumerated bridge filenames by loading UI assets. Validation now derives the same exact allowed filenames without reading absent UI resources. Hash, path, nonce, identity and reparse checks remain in place; staging still loads and verifies actual assets.

Focused verification: core-restart native policy 35 checks; assetless cached-session recovery 12 checks; browser Ready/restart UI cases; play-profile regression 759 assertions; Buddy workflow regression. The actual packaged 1.2.31 assembly also recovered a synthetic ended B42 session from a host with no asset bundle. Real game/Steam were not invoked. The first custom native-test host accidentally accepted worker arguments and recursively launched test helpers; all affected helpers were stopped by exact owned test image path. The host now rejects unknown arguments and injects a synthetic Steam boundary; the final isolated rerun passed. An older broad `profile-ui-tests.cjs` still contains obsolete eight-navigation/manual-query assertions and fails before reaching the changed connection label; the focused real DOM direct-server-launch test passed instead.
